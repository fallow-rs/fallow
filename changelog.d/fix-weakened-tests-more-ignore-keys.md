### Fixed

- **`fallow audit` reports a new entry in more config keys that hide findings.** The `weakened-tests` kind `ignore-pattern` now also compares these keys: `entry`, `supportEntry`, `dynamicallyLoaded`, `publicPackages`, `usedClassMembers`, `ignoreDependencies`, `ignoreBinaries`, `ignoreUnresolvedImports`, `ignoreExports`, `ignoreCatalogReferences`, `ignoreDependencyOverrides`, `production.ignore`, `health.ignore`, `duplicates.ignore`, `duplicates.ignoredClones` and `boundaries.coverage.allowUnmatched`. A new or broader entry gives a finding, and the evidence names the key. A narrower entry, or an entry that a base entry or a built-in default already covers, gives no finding. The finding message tells what the entry does: it removes paths from the analysis, hides findings, or makes more code count as used. An `ignoreFindings` finding now says that the change hides findings, because that key does not remove paths from the analysis.
