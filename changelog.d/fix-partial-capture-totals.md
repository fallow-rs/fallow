### Changed

- **Runtime coverage totals are null for a partial capture.** A Fallow Cloud partial capture (`capturePolicy: positive_only`, from the Vercel integration) records only the functions that ran. Before, the JSON report still gave the cloud's `summary.functions_tracked`, `summary.functions_unhit` and `summary.coverage_percent` as numbers, and the GitHub step summary and the `jq` summary printed them, so a script could read a coverage percent that the data cannot support. Now these three fields are null for a partial capture, `summary.functions_untracked` also counts the functions without a call, and the new `summary.capture_policy` field is `positive_only`. The human health line and the human summary no longer print an unhit count for a partial capture. Because the three fields are now nullable, these envelopes bump their schema version: `fallow health` to 13, `fallow audit` to 14, the bare combined output to 15, `fallow audit --brief` to 14, and `fallow coverage analyze` to `"3"`. A full capture gives the same numbers as before.
