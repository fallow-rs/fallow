### Added

- **`effect.schemaExportsAsTypes` reports unused Effect schemas as unused types.** An exported Effect schema defines a runtime value and a type (`typeof User.Type`). Teams that keep exported types as contracts can now treat schemas the same way: with `{ "effect": { "schemaExportsAsTypes": true } }`, fallow reports an unused schema export under `unused-types`, not under `unused-exports`. Set `"unused-types": "off"` to hide these findings. A schema is a class that extends a `Schema` class factory (`Schema.Class`, `Schema.TaggedClass`, `Schema.TaggedError`, `Schema.TaggedRequest`, `Schema.Error`, `Schema.ErrorClass`, `Schema.TaggedErrorClass`, `Schema.Opaque`), a subclass of such a class, or a const whose value is a `Schema` constructor, member or pipe chain, for example `Schema.Struct({...})`, `Schema.String` or `Schema.String.pipe(Schema.brand("Id"))`. `Schema` must be an import from `effect`, `effect/Schema` or `@effect/schema`, so a local object with the same name does not match. A value that a schema function returns, such as `Schema.decodeUnknownSync(User)` or `User.make({...})`, stays an unused export. An `unused-export` suppression comment on a schema export keeps its effect, and `unused-type` comments work too. `fallow fix` does not change these exports, the same as for other unused types. In `unused_types[]`, such a finding has `is_type_only: false`, because the export is a value. When a schema and its same-name type alias (`export type User = typeof User.Type`) are both unused, fallow reports one finding at the schema, because the two have the same finding id. The option is off by default, so the output does not change. Older versions reject the `effect` key, so pair it with `minimumVersion`. The extraction cache version changes, so the first run after the update parses every file again.
