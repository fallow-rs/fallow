### Fixed

- **`fallow dead-code` no longer makes entry points of the arguments that a package script gives to its script or to a program that it does not know.** In `node tool.js src/**/*.js`, `node` runs `tool.js` only, so the glob after the script is data and no longer makes every file in `src/` an entry point. The same applies to `tsx`, `ts-node`, `bun`, `deno run`, `nodemon`, a shell, and to the value of an option after the script, such as `--input src/lib/b.js`. A program that fallow does not know, such as `watchee -f './src/**/*'`, makes no entry points from its arguments. The rules also apply to the shell helpers that a script runs, to CI steps, and to Dockerfile commands. Test runners, bundlers, and compilers (`mocha`, `vitest`, `jest`, `esbuild`, `tsup`, `webpack`, `tsc`, and others) keep their file arguments as entry points. A relative module path of a runtime flag that loads code (`-r ./setup.js`, `--import ./register.js`, `bun --preload ./preload.js`) stays an entry point. Thanks @waldoluisribeiro for the report.
  (Closes [#3967](https://github.com/fallow-rs/fallow/issues/3967))
