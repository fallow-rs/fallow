### Security

- **The analysis caches no longer write through a symlink that leaves the project.** A cloned repository could commit `.fallow`, a directory in it, or a cache file such as `.fallow/.gitignore` as a symlink to a path outside the project. An analysis run then wrote through that link. It created or overwrote the outside file with the content `*` (the cache `.gitignore`), or it wrote cache files into the outside directory. This affected the extraction cache, the graph cache, the duplication token cache, the churn cache, the flag age cache, the audit and security base snapshot caches, the walkthrough state of `audit`, and the default snapshot path of `health --save-snapshot`. Each of these writers now checks the path before it writes. When the cache directory, a directory below it, or the file is a symlink that resolves outside the project, or a dangling link, the writer skips the cache save and the analysis continues. `health --save-snapshot` stops with an error in that case, and `audit-cache prune` does not delete through such a link. A link that stays inside the project still works. When `cache.dir` or `FALLOW_CACHE_DIR` points outside the project, for example `../shared-cache`, the check starts at that directory, so a link at the directory itself stays allowed.
