### Fixed

- **`unlisted-dependency` now reports a package that a tool config needs and that no manifest lists.** A tsconfig `compilerOptions.plugins[].name` names a language service plugin that TypeScript loads by name. An Expo app config that sets `userInterfaceStyle` (at the top level, or under `android`) needs `expo-system-ui` for the Android build. Fallow now reports the package when the manifest that owns the config, an ancestor manifest, and the root manifest do not list it. The finding points at the config value. A path, a Node.js builtin, a plugin that editor extensions ship (for example `typescript-svelte-plugin`), a config in `ignorePatterns`, and a package in `ignoreDependencies` give no finding. A `--production` run skips a tsconfig plugin, because only the editor loads it.
