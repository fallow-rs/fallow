### Added

- **`banned-import` rules accept `allowNames`.** A rule can now ban a package and keep some of its exports: `{ "kind": "banned-import", "specifiers": ["three"], "allowNames": ["Vector3", "Quaternion"] }`. Each entry is an exact imported name, with no globs, and `default` allows a default import. The rule compares the source-side name, so `import { Mesh as Vector3 }` reports `three: Mesh`. A namespace import, a star re-export and a side-effect import always report, because fallow cannot prove that they stay in the list. `allowNames` on another rule kind, a blank entry and an entry with `*` are load errors. `allowNames` does not cover `require()`, `import()` or `import x = require()`, because `banned-import` does not read them. A finding of such a rule has `matched` set to `<specifier>: <binding>`, with `three: Mesh`, `three: default`, `three: *` or `three: side-effect`. `fallow guard` and `fallow rule-pack list` show the list. Rules without `allowNames` keep their output. Adding `allowNames` to a rule changes `matched` on the findings of that rule, so it changes their baseline keys and finding ids. Re-save the baseline in the same commit. `--fail-on-baseline-growth` reports the new keys. For a deny list, use `banned-call` with `three.Mesh`. `banned-call` reports calls and `new` expressions. It does not report the import, a re-export, `extends Mesh` or a value reference such as `const body = Mesh`. To restrict every static import of a package, use `allowNames`. Thanks @Smrtnyk for the report. (Closes [#4072](https://github.com/fallow-rs/fallow/issues/4072))
