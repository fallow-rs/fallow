### Added

- **`client-server-leak` now checks React Router Framework Mode apps.** React Router code has no `"use client"` directive, so the rule had no starting point in such an app. When the React Router plugin is active, route modules (`root.tsx` included) are client roots. A route module is a file that the route config names, the root route, or a route file of the route directory. A helper next to a `route.*` file and a test file are not roots. Only the code that React Router keeps in the client build counts: an import, a re-export or a `process.env.X` / `import.meta.env.X` read that only `loader`, `action`, `middleware` or `headers` use is not followed. This also applies to a route module that another module imports. A secret read in the route component itself is reported. An env read in another form, such as `const { X } = process.env`, counts for the whole route module. Files named `*.client.*` or under a `.client/` directory are client roots, and files named `*.server.*` or under a `.server/` directory are `server-only-import` sinks, in the packages where the plugin is active. Such an app no longer gets the `client-server-leak-no-client-roots` diagnostic.
  (Closes [#4582](https://github.com/fallow-rs/fallow/issues/4582))
