### Fixed

- **`fallow audit` no longer runs the duplication analysis when the config has `duplicates.enabled: false`.** The audit read only its own `audit.dupes` key, so a project that turned duplication detection off still got clone groups in the audit report and in the verdict. `duplicates.enabled` is now the default of the duplication sub-analysis. An explicit `audit.dupes: true` and `fallow audit --only dupes` still run it. The programmatic audit and the MCP `audit` tool follow the same rule. The summary marks the sub-analysis as skipped. A `--dupes-baseline` flag is then ignored, and the run does not fail on it. Such an audit records no impact entry, as with `audit.dupes: false`.
