### Fixed

- **Each run of a multi-analysis SARIF document now has its own category.** GitHub code scanning reads the `automationDetails.id` of a run as `category/run-id`: the category is the text before the last `/`. GitHub rejects an upload with two runs that have the same tool and the same category. Before, the dead-code run and the health run of one document had no id, so `upload-sarif` gave them the same category and the upload failed. Now each id ends with a `/`, so the full id is the category. Bare `fallow --format sarif` gives the ids `fallow/dead-code/`, `fallow/dupes/` and `fallow/health/`. `fallow audit --format sarif` gives `fallow/audit/dead-code/`, `fallow/audit/dupes/`, `fallow/audit/health/` and `fallow/audit/diff-risk/`. `fallow report --from <file> --format sarif` gives the same ids as the direct output. The SARIF of a single command, such as `fallow dead-code --format sarif`, does not change.
- **Migration note for code scanning.** The `category:` input of `upload-sarif` does not apply to a run that already has an id. The runs of the documents above therefore use the categories in their ids, also when a workflow sets its own category. Alerts from these runs move to the new categories once. GitHub can show the alerts of the old category as closed after the first upload. The `fallow/dupes` and `fallow/audit/diff-risk` ids also change, to `fallow/dupes/` and `fallow/audit/diff-risk/`.
