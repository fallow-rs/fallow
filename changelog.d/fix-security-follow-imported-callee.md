### Fixed

- **`fallow security` no longer reports a call of a shallow-safe project function as a library sink.** Some rows match a callee by name only, for example `request(url)` for `ssrf` and `merge(a, b)` for `prototype-pollution`. When a module imports that function directly from another project file (a named, aliased or default `import`), the analysis now reads the body of the function in that file. A body is shallow-safe when it calls only shallow `Object` builtins such as `Object.assign({}, ...)`, `Object.keys` or `Object.entries`, and writes a member only one level deep on an object that the function creates. The call is then not a candidate. The same check now also applies to a local function, so a shallow copy such as `const copy = Object.assign({}, obj); copy[k] = v` no longer keeps the call of it. A recursive merge, a write to a parameter, a write two levels deep, `fetch` or any other call keep the candidate. A function from an external package, a re-export chain and a namespace import (`utils.merge()`) also stay candidates. (Closes [#4611](https://github.com/fallow-rs/fallow/issues/4611))
