### Added

- **A boundary zone can list its public entry files with `publicFiles`.** Since 3.31.0, the boundary check follows a named or default import through re-export chains and judges it by the file that declares the symbol. That made the one-public-entry-file pattern (for example `src/modules/billing/index.ts`) report every import through the entry file. Now a zone can set `"publicFiles": ["src/modules/billing/index.ts"]`. A file of another zone may then import only those files of the zone, and the chain walk stops at a public entry file. A deep import that a rule allows gets a finding with `reason: "internal_file"` and `public_files`, which names the files to import instead. On an `autoDiscover` zone, each glob is relative to each discovered folder, so `"publicFiles": ["index.ts"]` gives each module its own entry file. The output omits `reason` for a zone-rule finding, so a project without `publicFiles` gets the same output as before. `fallow list --boundaries --format json` shows the `public_files` globs of a zone. (Closes [#4760](https://github.com/fallow-rs/fallow/issues/4760))
