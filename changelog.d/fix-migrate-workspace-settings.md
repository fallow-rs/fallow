### Fixed

- **`fallow migrate` now translates the settings in a `workspaces` map of the source config.** Before, the migration dropped every per-workspace setting with one warning, so a monorepo config lost its entry files and ignore lists. The migration now puts the workspace path in front of each pattern, so `packages/*` becomes the `packages/*/` prefix. It writes `entry` patterns to `entry` and `ignore` patterns to `ignoreFindings`. It merges `ignoreDependencies` into the global list, because fallow has no per-workspace list. It writes `ignoreIssues` to `overrides` and `ignoreExports` where the issue types map. Each setting without a fallow equivalent, such as `project`, gets a warning that names the exact field.
- **`fallow migrate` no longer writes entry patterns that match no file.** The production marker (a trailing `!`) stayed in the pattern, so `src/main.ts!` matched no file and the entry was lost. The migration now removes the marker. A negated entry pattern gets a warning, because fallow `entry` cannot exclude files.
- **`fallow migrate` now translates the root `includeEntryExports` and `ignoreIssues` settings.** Before, the migration reported them as settings without a fallow equivalent.
