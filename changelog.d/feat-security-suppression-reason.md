### Added

- **`fallow audit` shows the reason of an added `fallow-ignore` comment.** An `added-suppression` finding for a `fallow-ignore` comment now has a `suppression` object with `kinds`, `reason` and `security_without_reason`. Write the reason after `--`, for example `// fallow-ignore-next-line security-sink -- the HTML is a constant template`. Every kind accepts this syntax. When the comment hides `security-sink` or `security-client-server-leak` and gives no reason, `security_without_reason` is `true`, the message says so, and the review brief evidence reads `fallow-ignore added (security-sink, no reason)`. A blanket comment without a kind does not set the flag. The signal covers only comments that the diff adds. To find existing security suppressions without a reason, run `fallow suppressions --format json` and select the markers with `reason_present: false`. The signal is advisory: the severity, the verdict and the exit code do not change, and existing suppressions keep working.
