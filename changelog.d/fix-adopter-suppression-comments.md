### Fixed

- **A `fallow-ignore-next-line` or `fallow-ignore-file` marker in a JSDoc comment now takes effect.** Before this fix, fallow skipped the markers `/** fallow-ignore-next-line unused-export */` and `/** fallow-ignore-file */` with no warning. It also skipped a marker on a ` * ` line of a multi-line JSDoc comment. Now a block comment accepts a marker at the start of any of its lines, and every marker line in one comment counts. A next-line marker applies to the line after the closing `*/`. This applies to every analysis, also to `fallow dupes` and to Vue, Svelte, Astro, MDX, HTML and CSS files. In those, a multi-line `/* */` comment counts when `/*` or `/**` is alone on its first line or the marker is on that line, so comment-like text in a string does not hide or add a marker. In a block comment, a line that starts with the marker word is a marker only when each target before an optional `-- reason` is an issue kind or looks like one, so a wrapped prose line such as ` * fallow-ignore-next-line is how you hide a finding.` is not a marker. A typo in an issue kind, such as `unused-exprt`, still gives the unknown-kind warning, and an unused JSDoc marker shows in the stale suppressions. The extraction cache and the duplication token cache get a new version, so a warm cache does not keep the old result.
