### Fixed

- **A read of `holder[name].prototype.member` on an object holder from another module counts the instance member as used.** A module can export an object of classes (`export default { websocket: WebSocket }`), and another module can import it and read `transports[name].prototype.handlesUpgrades`. Fallow reported `handlesUpgrades` as an unused class member. The member pass now follows the import one hop to the holder, also behind re-exports, and credits the member on each class that the key can select. A static key or a string-literal key selects one class. Another computed key selects each class. An exported holder in the same module (`export const transports = { ... }`) also works now. Objects built at runtime, spreads, and values passed through function calls are not followed. (Closes [#4724](https://github.com/fallow-rs/fallow/issues/4724))
