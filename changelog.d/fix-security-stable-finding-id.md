### Fixed

- **A stored security verdict now survives an edit that moves the sink to another line.** Each `fallow security` finding has a new `stable_finding_id` of the form `sec1:<16 hex digits>`. It hashes the rule, the project-relative path and the exact source text of the full sink expression (the full assignment, or the full call with all arguments), so whitespace, comments, line breaks, trailing commas and an edit above the sink do not change it. A hard-coded secret hashes its variable name and provider family, never the value. A client-server leak hashes the paths of its first and last trace hop and the names of the env secrets that it reads. Identical sinks in one file get the suffix `~1`, `~2` and so on, and a sink that an inline comment suppresses keeps its suffix position. A sink in Vue, Svelte or Angular template markup has no `stable_finding_id`; key its verdict by `finding_id`. `fallow security survivors` accepts this id or `finding_id` in a verdict, and the output stays keyed by `finding_id`. The location-based `finding_id` and the SARIF fingerprint do not change. (Closes [#4429](https://github.com/fallow-rs/fallow/issues/4429))
