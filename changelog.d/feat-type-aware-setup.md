### Added

- **`fallow type-aware setup` installs the type-aware companion for a binary that did not come from npm.** A Homebrew, `cargo install` or release-archive binary on macOS or Linux now gets the companion with one command. The command asks Node for its platform and architecture, downloads the bundle of its own version from the GitHub release, and checks the signature with the release key that the binary holds before it unpacks. The bundle goes into a versioned user directory, and Fallow checks that directory after `FALLOW_TYPE_AWARE_BIN` and the sibling of the executable. `--from <file>` installs a copied bundle on a machine with no route to GitHub. The download honors `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` and `FALLOW_CA_BUNDLE`. `fallow type-aware cleanup` removes the companions of other versions. The first bundles appear with the release that contains this change. `type-aware status` reports `discovery_source: "setup-directory"` for such a companion.
  (Closes [#4630](https://github.com/fallow-rs/fallow/issues/4630))

### Changed

- **A type-aware companion of another Fallow release stays valid while it speaks the same wire protocol.** Fallow compared the companion package version with its own version, so each upgrade needed a new companion. It now compares only the wire protocol version, so a companion stays in use until the protocol changes. The wire protocol is now 8, because the format changed three times at version 7. A CI check now ties the version to a hash of the wire contract, so a format change cannot ship at the old version. Companions of earlier releases are not accepted: such a companion refuses the request, and the error then names `fallow type-aware setup` and the npm install. The npm launcher still selects the companion of the exact version.
