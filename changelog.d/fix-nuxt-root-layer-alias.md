### Fixed

- **A Nuxt `#layers/<name>/` import now resolves to the named layer first, and a missing target reports as an unresolved import.** Nuxt points `#layers/<name>/` at the project root when the root `nuxt.config` sets `$meta.name`, and at each named local layer. A `layers/<name>` directory without a Nuxt config took the import through the `#layers/` fallback, so the real target in the root reported as an unused file. Now the longest plugin alias prefix wins, as for TypeScript `paths` patterns. An import of a missing file through a named layer alias was silent, because the Nuxt `#` virtual module prefix covered it. Now it reports as an unresolved import. A missing target through the `#layers/` fallback stays silent, because that fallback can address a layer that fallow does not model.
