### Changed

- **The MCP server refuses a response over 1,000,000 bytes, and the refusal names the parameters that make the output smaller.** Before, the default cap was 16 MiB. That is far above the context window of an agent, and many MCP hosts cut a large result on their side, so the agent got invalid JSON. On a large public monorepo, an unfiltered `analyze` returned 5.6 MB and `find_dupes` returned 9.2 MB. Both now get a valid refusal (`isError`, `exit_code: 2`, `code: FALLOW_MCP_SUBPROCESS_OUTPUT_LIMIT`). The cap is the same as the default result cap of Code Mode. The refusal body has a new `narrow` array with the parameter names of the refused tool that reduce its output, for example `issue_types`, `file` and `workspace` on `analyze`, or `top` on `find_dupes` and `check_health`. Set `FALLOW_MCP_MAX_OUTPUT_BYTES` in the server environment to use a different cap, up to 16 MiB. The `max_output_bytes` parameter of a call still only lowers the cap.
