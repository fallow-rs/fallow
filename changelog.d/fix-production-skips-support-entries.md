### Changed

- **Production mode reports more dead code: user support entries take no part.** Before, `--production` kept the files of a user `framework[]` entry with the `support` role as entry points. So an export, a file or a dependency that only a dev tool script used still counted as used. Now, in production mode (`--production`, `production: true` or `production: { deadCode: true }`), a file that only user support entries match is like a test file. It is not an entry point, it gets no finding, and its imports credit nothing. A file that a runtime root also seeds, such as a config `entry` glob or a production package.json script, stays a runtime root. A file that the analyzed code imports stays a normal module. Built-in plugin support entries, normal runs, `health` and `dupes` do not change. Expect new `unused-export`, `unused-file` and `unused-dependency` findings in a production run of a project that declares tool scripts this way. (Closes [#4068](https://github.com/fallow-rs/fallow/issues/4068))
