### Changed

- **Production mode reports more dead code: user support entries take no part.** Before, `--production` kept the files of a user `framework[]` entry with an explicit `"entryPointRole": "support"` as entry points. So an export, a file or a dependency that only a dev tool script used still counted as used. Now, in production mode (`--production`, `production: true` or `production: { deadCode: true }`), a file that only user entries with an explicit `"entryPointRole": "support"` match is like a test file. A user plugin that sets no role keeps its entries, although its effective role is still `support`. It is not an entry point, it gets no finding, and its imports credit nothing. A file that a runtime root also seeds, such as a config `entry` glob or a production package.json script, stays a runtime root. A file that the analyzed code imports stays a normal module. Built-in plugin support entries, normal runs and `dupes` do not change. Expect new `unused-export`, `unused-file` and `unused-dependency` findings in a production run of a project that declares tool scripts this way. The production `health` vital signs that come from dead code, such as `dead_export_pct`, follow the new result. (Closes [#4068](https://github.com/fallow-rs/fallow/issues/4068))
