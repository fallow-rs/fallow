### Added

- **New `unlisted-binaries` rule.** Fallow now reports a binary that a `package.json` script or a process call in source runs, when no installed or listed package provides it. Source calls are `spawn`, `spawnSync`, `exec`, `execSync`, `execFile` and `execFileSync` of `node:child_process`, `execa`, `execaCommand` and the `$` template of `execa` and `zx`, and `Bun.spawn` and `Bun.$`, each with a literal command. A binary counts as provided when a `node_modules/.bin` link exists, when a declared dependency or a workspace package declares it in `bin`, or when it maps to a declared dependency. Shell builtins, commands that `npx` or `pnpm dlx` download, and a fixed list of common operating-system tools (such as `git`, `ssh-keygen`, `curl` and `ffmpeg`) are skipped. A project without a root `node_modules` reports nothing. The rule defaults to `warn`.
- **New `ignoreBinaries` config.** It takes exact binary names and globs, like `ignoreDependencies`. Each finding carries an `add-to-config` action for it. `fallow migrate` maps `ignoreBinaries` (top level and per workspace) and the `binaries` rule.
- The JSON envelope gains the `unlisted_binaries` array and `summary.unlisted_binaries`. SARIF, CodeClimate, compact, markdown, human output, GitHub annotations and summaries, the LSP, the MCP `analyze` tool and the VS Code extension report the finding. The `--unlisted-binaries` flag scopes a run to it.
- The parse cache version changes because the cache now stores the command calls of each file. The first run after the upgrade parses every file again.
