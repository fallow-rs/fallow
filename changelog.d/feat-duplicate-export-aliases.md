### Added

- **The new `duplicate-export-aliases` rule reports one binding that one file exports under two or more names.** Examples are `export const layer = make(); export default layer;`, `export { a, a as b }` and `export { a as default }` next to `export const a`. Named re-exports of one source name from one source also count. Fallow does not report two bindings with the same value, a value and a type that share a name, function overloads, `export *`, or a file with CommonJS exports (`export =`). The existing `duplicate-exports` rule does not change: it still reports one export name in several files. The new rule defaults to `warn`, so a run without `--fail-on-issues` keeps its exit code. `--fail-on-issues` promotes `warn` to `error`, so a project with aliased exports can now exit with code 1 under that flag. To keep the old result, set `"duplicate-export-aliases": "off"` in `rules`.
  - The JSON output has the new array `duplicate_export_aliases`. Each entry has `path`, `local_name`, `export_names`, `line`, `col`, `locations` (one `{export_name, line, col}` for each name), `finding_id`, and `actions`. The actions are a manual `remove-duplicate` fix and a line suppression. Neither action is auto-fixable. `summary.duplicate_export_aliases` counts the findings.
  - SARIF and CodeClimate use the rule id `fallow/duplicate-export-alias`. The human, compact, markdown, GitHub summary, GitHub annotation, LSP, and baseline outputs report the finding too.
  - `ignoreExports` exempts a whole file with `"*"`, or a binding when the entry lists one of its names. `// fallow-ignore-next-line duplicate-export-alias` above any of the names hides the finding. `// fallow-ignore-file duplicate-export-alias` hides all findings of the file.
  - `--duplicate-export-aliases` limits a dead-code run to this rule.
  - `fallow migrate` maps the `duplicates` issue type of the source config to `duplicate-export-aliases`, and still maps it to `duplicate-exports`. A file-scoped `duplicates` entry in `ignoreIssues` now becomes an override that turns `duplicate-export-aliases` off for the glob. Before this change, migrate warned that the entry had no equivalent.
