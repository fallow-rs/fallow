### Fixed

- **CodeClimate clone fingerprints no longer change with CRLF line endings.** The CodeClimate fingerprint of a clone instance hashes the first 64 characters of the clone fragment. Before, these characters kept each `\r`, so a Windows checkout with `core.autocrlf` gave other fingerprints than a Linux checkout of the same code. GitLab Code Quality then reported each clone as new and as fixed. The `review-github`, `review-gitlab`, `pr-comment-github` and `pr-comment-gitlab` formats merge and sort by this fingerprint, so their output changed too, in `fallow dupes` and in `fallow audit`. The hash now leaves out `\r`. Files with LF line endings keep their fingerprints. A project with CRLF files gets new fingerprints one time, and they then match the fingerprints of an LF checkout. When two clone groups share one `dup:` hash, the order of their `-r1` and `-r2` suffixes also no longer changes with the line endings. The `fallow audit` clone-group key also leaves out `\r`, and the audit base snapshot cache moves to version 21.
