### Fixed

- **`banned-call` rules and `boundaries.calls.forbidden` now match `new` expressions.** A `Date` pattern reported `Date()` but not `new Date()`. The `ai-safe-repo` template bans `Function`, and it did not report `new Function()`. Now a pattern matches both forms. The new finding has `matched` or `callee` set to `new Date`, and `new T.Group()` reports `new T.Group`. Findings for the call form keep their id, fingerprint and baseline key. A file with `Date()` and `new Date()` gives two findings, one for each form. A rule with severity `error` can now fail the gate, and a saved baseline does not cover the new findings. To preview them, run `fallow rule-pack test`. To accept them, set the rule severity to `warn` or save the baseline again. `banned-effect` does not change. It reads call expressions only. The extraction cache version changes because cached modules hold no `new` sites. Thanks @Smrtnyk for the report. (Closes [#4071](https://github.com/fallow-rs/fallow/issues/4071))
