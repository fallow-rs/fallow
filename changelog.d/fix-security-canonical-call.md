### Fixed

- **`fallow security` reports the usual forms of a sink call.** These calls now give a candidate: `new Handlebars.SafeString(x)` (`template-escape-bypass`), `this.sanitizer.bypassSecurityTrustHtml(x)` (`angular-trusted-html`), `$("#p").html(x)` (`jquery-html`) and `console.log("login", secret)` (`secret-pii-log`). The extractor now reads each call and `new` expression in one way, so a sink behind `this.`, a call result or a local alias gets the same candidate as the plain form. A matcher row now says which call forms it accepts (`forms`) and which arguments it reads (`arguments`). Log rows read every non-literal argument. A `this.m(x)` call gives a candidate only in a class that extends a class from outside the file and does not declare `m` itself, such as `this.$queryRawUnsafe(x)` in a subclass of a database client. A `this.m(x)` call in other code (an own method, a method of a local base class, a function on a prototype, or a method of an options object) gives none, as before. A long fluent chain keeps the candidate of a sink at its end. A member that a destructuring takes from a `require()` binding of a Node.js module (`const { exec } = cp`) now resolves to the module path. Security controls and framework request sources also read callees behind `this.` and call results, so `this.router.get("/", handler)` now marks `req` as request input. Projects can get new candidates, and fewer calls show as unresolved callees. The cache version changes, so the first run after the update parses each file again. (#4940)
