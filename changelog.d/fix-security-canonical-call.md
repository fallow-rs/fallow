### Fixed

- **`fallow security` reports the usual forms of a sink call.** These calls now give a candidate: `new Handlebars.SafeString(x)` (`template-escape-bypass`), `this.sanitizer.bypassSecurityTrustHtml(x)` (`angular-trusted-html`), `$("#p").html(x)` (`jquery-html`) and `console.log("login", secret)` (`secret-pii-log`). The extractor now reads each call and `new` expression in one way, so a sink behind `this.`, a call result or a local alias gets the same candidate as the plain form. A matcher row now says which call forms it accepts (`forms`) and which arguments it reads (`arguments`). Log rows read every non-literal argument. A call of a method that the enclosing class or object literal declares itself (`this.query(x)`) gives no candidate. A method that the class inherits from a library (`this.$queryRawUnsafe(x)` in a subclass of a database client) still gives one. A long fluent chain keeps the candidate of a sink at its end. A member that a destructuring takes from a `require()` binding of a Node.js module (`const { exec } = cp`) now resolves to the module path. Security controls and framework request sources also read callees behind `this.` and call results, so `this.router.get("/", handler)` now marks `req` as request input. Projects can get new candidates, and fewer calls show as unresolved callees. The cache version changes, so the first run after the update parses each file again. (#4940)
