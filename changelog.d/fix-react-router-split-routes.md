### Fixed

- **React Router route files that an imported module declares are now entry points.** A `routes.ts` file can import route arrays from other local modules and spread or merge them, for example `[...coreRoutes]` or `mergeRoutes(coreRoutes, extendedRoutes)`. The React Router plugin read only the expressions in `routes.ts` itself. `fallow dead-code` then reported the route files of the imported modules as unused files, and also each file that only these route files import. The plugin now follows spread elements, named and default imports from relative specifiers, `export { a as b }`, `export { a } from` and `export * from`. A `.js` specifier that names a TypeScript source also resolves. Route file paths in an imported module stay relative to the directory of `routes.ts`, the same as React Router resolves them.
- **React Router route files with brackets in their path are now entry points.** The plugin used each route file path as a glob pattern. A segment such as `[workspaceSlug]` then matched one character and not the directory with that name, so `fallow dead-code` reported the route file as unused. The plugin now escapes the path before it makes the pattern.
