### Changed

- **`fallow mutation` runs the test files of one Vitest mutant run in one worker.** Vitest starts a new worker for each test file of a run when module isolation is on. After the dry run, the Vitest adapter now runs the test files once more in one shared worker. When each test gives the same result, the mutant runs of the companion use one worker for all of their test files. Each run still starts a new worker, so the modules stay fresh for each mutant. A test that needs a fresh worker for each file makes the two dry runs differ, and the runs then stay isolated. A kill in a later file of a shared worker counts only when the file also detects the mutant alone, and the retry of a survivor always runs each file in its own worker. On unjs/ufo, where a mutant has covering tests in almost three files, this cut the worker processes by a quarter, and no verdict changed.
  (Part of [#4341](https://github.com/fallow-rs/fallow/issues/4341))
