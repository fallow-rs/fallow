### Fixed

- **`fallow dead-code` reports a module that wraps a same-named import as a duplicate export again.** A module that imports `encode` under an alias (`import { encode as base64 } from "./Base64"`) and declares its own `encode` is a wrapper. Importers see two `encode` exports with different behavior, so the `duplicate-exports` rule reports the pair. Since 3.35.0 the rule dropped such a module. The rule still drops an overlay module that also declares `export * from` the same module, for example a native binding that one class extends. This rule is `error` by default, so CI can show new findings after the upgrade. To keep a wrapper on purpose, add `// fallow-ignore-next-line duplicate-export` above its export, or add the name to `ignoreExports`. (Closes [#4024](https://github.com/fallow-rs/fallow/issues/4024))
