### Added

- **The review brief reports security sink substitution.** A change that removes a security sink and adds a different sink of the same class in the same source file now gives a `security-check-removed` signal in `weakening[]` of `fallow audit --brief` and `fallow review`. A rule that flags `new Function` does not flag `vm.runInNewContext`, so the swap silences the rule and keeps the risk. The classes are code execution (`eval`, `new Function`, `vm.runIn*`, `vm.compileFunction`, `new vm.Script`) and HTML (`innerHTML`, `outerHTML`, `srcdoc`, `srcDoc`, `insertAdjacentHTML`, `setHTMLUnsafe`, `createContextualFragment`, `document.write`, `dangerouslySetInnerHTML`). The evidence reads `new Function sink replaced by vm.runInNewContext`. A sink that moves into an object key under a JSX spread, a computed member such as `globalThis['eval']`, or an alias reads `dangerouslySetInnerHTML sink moved into an object key`. A sink that only moves in the file, or goes away, gives no signal. Test files do not take part. The kind set and the keys do not change.
