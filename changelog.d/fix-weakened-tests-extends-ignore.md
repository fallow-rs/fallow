### Fixed

- **`fallow audit` reads the full config chain for a less strict config.** The `weakened-tests` check of the Fallow config now finds the config file the same way as the loader, from the analysis root up to the git root. It follows each relative `extends` file at the base and at the head. A lower rule severity in an extended file, or a removed `extends` entry, now gives a `rule-severity` finding on the changed file. A value that an `npm:` package or an `https://` URL can set does not compare, because the audit cannot read it at the base. A rule that moves between config files with the same severity gives no finding. A finding on a config file in a parent directory of the root has a path that starts with `../`, and the GitHub and GitLab output resolve it against the repository prefix.
- **`fallow audit` reports a new ignore entry in the Fallow config.** A new or broader `ignorePatterns` or `ignoreFindings` entry, or a removed `!` exception, now gives a `weakened-tests` finding with the new kind `ignore-pattern`. An `ignoreFindings` list that changes to only `!` entries also reports, because it hides every other path. A removed or narrower entry, or an entry that a built-in default already covers, gives no finding. The finding takes the stricter of the base and the head `weakened-tests` severity, and a head suppression comment does not hide it. The audit brief shows it as a `suppression-added` signal.
