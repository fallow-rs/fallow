### Fixed

- **`fallow mutation` now prunes mutants in functions that write through an ORM or a query builder.** The side-effect prune took its database sinks from the security catalogue, which matches only injection shapes. A safe write such as `db.insert(records).values({ value })` matched no row, so the plan kept its mutants and a run could write to a real database. The plan now also treats member calls with a database write method name (`insert`, `insertInto`, `update`, `delete`, `create`, `upsert`, `save`, `transaction` and similar) as sinks. This applies only in a module that imports a database client package, such as `drizzle-orm`, `@prisma/client`, `kysely` or `pg`, or that imports a project module that imports one. `--allow-side-effects` keeps these mutants. Projects with ORM writes can see more `pruned` mutants and a different score.
  (Closes [#3641](https://github.com/fallow-rs/fallow/issues/3641))
