### Fixed

- **`fallow mutation` now prunes mutants in functions that write through an ORM or a query builder.** The side-effect prune took its database sinks from the security catalogue, which matches only injection shapes. A safe write such as `db.insert(records).values({ value })` matched no row, so the plan kept its mutants and a run could write to a real database. The plan now also treats member calls with a database write method name (`insert`, `insertOne`, `update`, `delete`, `del`, `create`, `upsert`, `save`, `$transaction` and similar) as sinks. This applies only in a module that loads a database client package, such as `drizzle-orm`, `@prisma/client`, `kysely`, `knex`, `mongodb` or `pg`, or that loads a project module that loads one. An ES import, a type-only import, a `require()` call and an `import()` call each count. `--allow-side-effects` keeps these mutants. Projects with ORM writes can see more `pruned` mutants and a different score.
  (Closes [#3641](https://github.com/fallow-rs/fallow/issues/3641))
