### Fixed

- **`fallow security --gate new` now fails when a change adds a secret read or a server-only import below line 1 of an existing client module.** A `client-server-leak` candidate now points at the env read or at the server-only import, not at line 1, column 0. The JSON `line`, `col`, `candidate.sink` and trace hops move to that location, and SARIF and the editor follow. A `secret-source` trace hop has a new `secret_reads` array that lists each read with its `name`, `line` and `col`, and the gate checks each of these lines. So a read that a change adds to a module with an older read also fails the gate. The stable finding id does not change. The first run after the upgrade rebuilds the extraction cache.
  (Closes [#4881](https://github.com/fallow-rs/fallow/issues/4881))
- **A secret read in a React Router `loader` no longer gives a `client-server-leak` candidate in the computed or the destructured form.** The route split now checks `process.env['X']` and `const { X } = process.env` the same as `process.env.X`, so the documented limit for these forms is gone. The `Next:` step of a direct secret read now talks about the env read, not about an import, in the CLI and in the editor hover.
  (Closes [#4882](https://github.com/fallow-rs/fallow/issues/4882))
