### Fixed

- **`fallow coverage analyze --cloud` keeps the production signals of Fallow Cloud.** The CLI read each runtime-context row into a fixed set of fields and dropped the rest. Each finding and hot path now has a `cloud_context` object with the row fields that the CLI does not read itself, for example `errors`, `performance.cpu`, `performance.browser`, `branches`, `covered_by_test` and `test_hit_count`. A blast-radius row from the cloud has `production_callers`, `caller_sites` and the caller counts in its `cloud_context`. The report-level `cloud_context` has the top-level fields, for example `capabilities` and `page`. The MCP tool `get_cloud_runtime_context` runs this command, so it now returns these signals too. The signals are context only and do not change a verdict.
- **`fallow inspect --file <path> --cloud` reads the browser and caller signals.** Each paired function now has `browser_long_frame_ms_per_hour`, `static_callers` and `production_callers`. The compact format shows them on the `prod` line, with at most two production callers by name.
