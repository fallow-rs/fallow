### Fixed

- **`fallow dead-code` now reads an alias replacement that a top-level constant holds as a path call.** A config such as `const I18N_STUB = path.resolve(__dirname, "test/stubs/i18n.ts")` with `alias: [{ find: "@/i18n/i18n", replacement: I18N_STUB }]` swaps a module for a stub. Fallow read such a constant only when it held a plain string, so it dropped this alias and reported the stub as an unused file or reported its exports as unused. Fallow now resolves a stable top-level `const` or `let` that holds `path.resolve(...)`, `path.join(...)`, `fileURLToPath(...)` or `new URL(...).pathname`, also through a chain of constants. A binding that the config writes again, changes or shadows keeps the old behavior. This applies to Vite, Vitest and webpack aliases. Aliases in Vitest `projects` entries and in `vitest.workspace` arrays now also read these constants and the local path helpers of the config file.
