### Fixed

- **`fallow migrate` now maps the namespace issue types `nsExports` and `nsTypes`.** Fallow reports an unused export or type that a consumer reads through a namespace as `unused-exports` or `unused-types`. So a `nsExports` or `nsTypes` entry in `rules`, `include`, `exclude` or `ignoreIssues` needs no own setting when the same scope sets `exports` or `types` the same way. An unset base rule counts as `"error"`, and a base rule that is off globally also covers an `ignoreIssues` entry. The migration warns only when the entry differs from its base type. Fallow cannot set the namespace findings apart, so `exports` and `types` control them too. Before, every such entry gave the warning `has no fallow equivalent`.
