### Fixed

- **A `code_execute` snippet now always ends near its `timeout_ms`.** The MCP server runs each Code Mode snippet in a separate process and kills that process at most 4 seconds after `timeout_ms`, or when the client cancels the call. The limit is 2 seconds after `timeout_ms` for a running snippet process, and up to 2 seconds more when the process must start first. Before, a snippet inside one long native builtin call (for example `Array.prototype.reverse` on an array-like object with a very large `length`) did not see the deadline or the cancel. The call then got no answer, used a full CPU core, and kept `fallow-mcp` running after the client disconnected. Host calls still run in the server process, so the shared parse store and the existing limits do not change.
