### Fixed

- **`fallow dead-code` no longer reports an import of a sibling build output file as unresolved.** A bundler can compile `src/loader.ts` and `src/app.ts` into one output folder as `loader.cjs` and `app.cjs`. The import `./app.cjs` or `./app.mjs` in a TypeScript file now resolves to `app.ts`, `app.tsx`, `app.mts` or `app.cts` in the same folder when the output file is not on disk.
- **`fallow dead-code` no longer reports the keys of the Metro `resolver.extraNodeModules` map as unlisted dependencies.** Metro maps each key to a folder, which is often generated. The React Native plugin reads the static keys of the map, as a property value or as a `config.resolver.extraNodeModules = {...}` assignment, and accepts imports of those names below the folder of the Metro config.
- **`fallow dead-code` now reads Vitest projects that `defineProject(...)` wraps.** A `test.projects` list such as `[defineProject(unitProject), defineProject({ test })]` now gives the `include` globs and the `setupFiles` of each project. Before, the test files and setup files of these projects were reported as unused.
- **`fallow dead-code` now treats a `file:` or `link:` folder dependency of a workspace package as a workspace.** Before, only the root `package.json` gave such workspaces. pnpm installs a `file:` folder as a copy in its store, so the files of a local package such as `apps/app/modules/native-text` were reported as unused.
