### Changed

- **`fallow audit --gate new-only` now reports the unused files and unused exports that a change creates outside the changed files.** A change can make code unused without a change to that code: it removes the last import of a file or an export, or a config change removes an entry point. The audit compared only the changed files, so it passed such a change. Now the audit keeps an unused file or unused export outside the changed files when the base does not report it, marks it `introduced: true`, and counts it in `attribution.dead_code_introduced`. An unused file or unused export outside the changed files that the base also reports stays out of the report, as before. When the change touches the config file, the base runs one more dead-code pass with the config of the base commit, so a removed entry point counts. That pass gives no evidence when the base config turns `unused-files` or `unused-exports` off. Code that the base config ignores (with `ignorePatterns`, `ignoreFindings`, `ignoreExports` or an override) does not count as introduced when the change stops ignoring it. An unused export in a file that was unreachable at the base does not count as introduced either. A `[PATH]` scope still bounds the report. `--gate all` keeps the report to the changed files. A cached base snapshot of an earlier version is not reused.
