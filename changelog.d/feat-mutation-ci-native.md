### Added

- **`fallow report` renders mutation results for CI.** The new flags `--mutation-report <PATH>` and `--mutation-not-run <REASON>` work with the pr-comment, review, `github-summary`, `github-annotations` and `codeclimate` formats. Survived mutants on changed lines appear as findings with the rule `fallow/mutation-survived` in the new **Tests** category: rows in the sticky comment, annotations, inline review comments and Code Quality entries, 20 at most for each render. The comment, the review summary and the job summary get one "Mutation testing" section, and the check run gets a `mutation` row and a `mutation-min-score` row. A survivor in a file that changed after the run is not shown. Without the flags, the output of `fallow report` does not change.
- **`fallow mutation` writes its score gate into the report.** A run with `--min-score` or `mutation.minScore` adds `gate_outcomes["mutation-min-score"]` to the `mutation` report, and exit code 1 reads that entry. The `gates-*` outputs of the Action and the `FALLOW_GATES_*` lists of GitLab name the gate. The Action has the new output `mutation-report-rendered`.
