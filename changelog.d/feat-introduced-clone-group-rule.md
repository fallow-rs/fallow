### Added

- **`fallow audit` can fail on a new clone group.** The new rule `introduced-clone-group` (`error`, `warn` or `off`) sets how a clone group takes part in the audit verdict and exit code. The default is `warn`, so the verdict does not change for current configs. With `error`, a clone group that the change introduces fails the audit with exit code 1. With `off`, the group stays in the report but does not change the verdict. Under `--gate new-only`, an inherited clone group never gates. Under `--gate all`, every clone group in the changed files follows the rule. With `overrides`, the rule resolves for the file of each copy, and the most severe result applies. So an override cannot exempt a clone group that has a copy outside the override. For generated code, use `duplicates.ignore` or `ignorePatterns`. `duplicates.threshold` does not change and can still fail the run. `fallow explain introduced-clone-group` describes the rule.
  (Closes [#4658](https://github.com/fallow-rs/fallow/issues/4658))
