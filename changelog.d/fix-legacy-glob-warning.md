### Changed

- **The warning for a config glob that matches fewer files since 3.34.0 now names the files and gives two fixes.** Since 3.34.0, a single `*` or `?` in a config path glob matches in one folder level only. The stderr warning for a glob that lost files gave only a count and a `**` rewrite. Now it names up to 3 of the lost files, then "and N more". It also tells you how to keep the one-level meaning: write the names in place of `*`, for example `{name1,name2}`. This config change stops the warning. The `**` rewrite stays as the second choice. For `entry` and `dynamicallyLoaded`, a lost file that another entry source declares, for example a plugin or `package.json`, does not count, because it is still an entry point. When no lost file remains, fallow prints no warning. Only the commands that find entry points, for example `fallow dead-code` and `fallow health`, check these two fields. The warning stays on stderr, `--quiet` hides it, and JSON output does not change.
