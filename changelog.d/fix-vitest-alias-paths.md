### Fixed

- **`fallow dead-code` no longer reports the exports of an alias replacement file when tsconfig maps the alias key to another file.** An entry such as `{ find: "src/clock", replacement: "./test/stubs/clock.ts" }` swaps a module for a stub, and tsconfig `paths` (`src/*`) or `baseUrl` also resolves `src/clock`. Fallow applies tsconfig before the alias, so the import reached the original file and the stub had no consumer. With `includeEntryExports`, fallow reported the exports of the stub as unused. Fallow now credits every export of the replacement file when a tsconfig maps the key to an existing file that is not the replacement. The check reads the nearest tsconfig of the replacement file and of the config file, their relative `extends` chain, and their `references`. This applies to Vite, Vitest and webpack aliases. Thanks @Smrtnyk for the report.
  (Closes [#4035](https://github.com/fallow-rs/fallow/issues/4035))
