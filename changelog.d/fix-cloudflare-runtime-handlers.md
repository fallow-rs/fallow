### Fixed

- **`fallow dead-code` no longer reports the Cloudflare Workers runtime handlers as unused class members.** The runtime calls these methods by name, so no project code calls them. A class that extends a base class of `cloudflare:workers` now gets credit for the handlers that the base class declares in `@cloudflare/workers-types`: `alarm`, `fetch`, `connect`, `webSocketMessage`, `webSocketClose` and `webSocketError` on `DurableObject`; `email`, `fetch`, `connect`, `queue`, `scheduled`, `tail`, `tailStream`, `test` and `trace` on `WorkerEntrypoint`; `run` on `WorkflowEntrypoint`. The base can come from a named import or a namespace import (`cf.DurableObject`). A subclass gets the same credit through a chain of local base classes, also when the module does not export a base class or a base class is generic. A default export and a renamed export (`export { Room as ChatRoom }`) get the credit too. A base class with the same name from another module gets no credit, and other methods stay reported. Known limit: a `static` method with a handler name also gets credit, although the runtime calls only instance methods.
  (Closes [#4649](https://github.com/fallow-rs/fallow/issues/4649))
- **`fallow dead-code` credits a Durable Object method that a Worker handler calls through its untyped `env` parameter.** In an object of the type `ExportedHandler<Env>` (through `satisfies`, `as` or a variable annotation), the second parameter of a handler such as `fetch` or `queue` now has the type `Env`. A stub call such as `env.ROOM.get(id).sayHello()` then credits `sayHello` on the Durable Object class of the binding. Known limits: the type name `ExportedHandler` matches without a check for a local type of the same name, and a handler that names a separate function (`{ fetch }`) gets no `env` type. The extraction cache version changes, so the first run after the upgrade parses every file again.
