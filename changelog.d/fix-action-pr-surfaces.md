### Fixed

- **The `comment-layout` input of the GitHub Action now changes the sticky comment.** `fallow report --from` ignored `FALLOW_PR_COMMENT_LAYOUT`, so `compact`, `gate-only` and `details` rendered the same comment as `default`. Now `compact` shows one row per section with its error and warning counts, `gate-only` shows the verdict and the gate line only, and `details` opens each section.
- **The live `fallow --format pr-comment-github` comment of the combined run is the same as the saved render.** The live run used a second design with a "Checks" table and "Top fixes", and it counted other findings than `fallow report --from`. Both now render through one path.
- **The PR comment, the review and the check run show finding text without escape characters.** A code span in a finding description stays a code span, a quoted name such as `'lodash'` becomes a code span, and only characters that can start Markdown or HTML get a backslash. Text such as `Changing \<string\> to ""` now reads ``Changing `<string>` to `""` ``.
- **The check run states the verdict of the sticky comment.** Its title was `Fallow`. It is now the comment verdict with the counts, for example `Quality gate failed: 4 errors, 15 warnings`, and its summary has one row per gate. When the Action emits workflow annotations, the check run leaves out its copy of the annotations, so each finding shows once.
- **The Action job messages count in the right number.** "Fallow found 1 issues" now reads "Fallow found 1 issue".
- **The job summary and the annotations use plain text.** The job summary has no emoji, middle dots or run times, and a bold value marks a breached metric in place of `**!**`. The refactoring-target annotation shows its priority (it was empty), a survived mutant annotation has the title `Survived mutant`, and the annotation advice is a short instruction. The job summary verdict uses the words of the sticky comment, and the action writes its own gate line only when the native summary did not render.

### Changed

- **The sticky PR comment states the verdict first, then the counts, then the details.** The verdict line is followed by the counts per severity (`19 findings: 4 errors, 15 warnings`) and the gate line, before the finding tables. The gate line no longer comes after the footer. Each rule id links to its docs page, the location is one code span (`src/a.ts:12`), and the severity column uses `error` and `warning`, the same words as the review comments and the annotations.
- **The gate line and the request line are shorter.** `Gate outcomes: failed error-severity-findings (3 at or above error) (none of which fails this run)` now reads `Gates: failed error-severity-findings (3 at or above error)`. The job status states whether the run failed. The request line appears only when a request did not apply or applied over an empty scope.
- **Inline review comments are easier to read.** `Other locations:` is now `Also in:`, a one-line range reads `src/a.ts:3` and not `src/a.ts:3-3`, `> Fix intent:` is now `**Fix:**`, and the review body no longer repeats the mutation result in one line before the mutation section.
- **Duplicate code findings name the size of the clone.** The CodeClimate description `Code clone dup:7308a6eb (14 lines, 2 instances)` is now `14 lines repeat in 2 places (clone group dup:7308a6eb)`.
- **The mutation section uses plain words.** A partial run names its reason in words (`the run reached its time budget`), a survived mutant description puts the code in code spans (``Changing `>=` to `>` in `isAdult` ``), the count table leaves out the `Not measured` column when it is 0, and the section no longer says `Scope: the changed lines.` for the default scope.
