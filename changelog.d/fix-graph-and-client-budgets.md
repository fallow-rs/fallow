### Fixed

- **A dense group of circular imports no longer makes the cycle check run for minutes.** The check stopped only after it listed 20 cycles of one group of files. A group with few short cycles and very many longer import paths made it follow tens of millions of imports. The check now stops after 500,000 imports per group and marks the group as capped, as it does at 20 cycles. When it stops before it finds a cycle, it still reports one shortest cycle of the group. Real projects use far fewer steps.
- **A V8 coverage file with a source map that points past its script no longer slows the health run.** Each such map made the map parser build a line table of 16 million lines. A map whose section starts after the last line of the generated script now does not apply to that script, in `fallow health` with V8 coverage and in `fallow health --runtime-coverage`.
- **A cloud answer with very many small JSON values now gives a clear error.** Before, such an answer passed the size limit and the parse could use all memory. The cloud reads now refuse an answer with more than 2 million JSON values.
- **`fallow agent install` keeps a normal indent in an MCP config file with a very wide indent.** The edit copied the indent of the first indented line at each nesting level, so a very wide indent made the file very large. The edit now keeps an indent of 8 characters or fewer, and uses two spaces in place of a wider one.
- **The type-aware config hash no longer times out on shared tsconfig `extends` entries.** The hash read a config once for each path that reached it. It now reads each config once, and it keeps the same hash for real projects, so stored type-aware baselines stay valid.
