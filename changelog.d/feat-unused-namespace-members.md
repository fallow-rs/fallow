### Added

- **New rule `unused-namespace-members` reports an unused member of an exported TypeScript namespace.** For `export namespace Legacy { export const used = 1; export const unused = 2 }`, fallow now reports `Legacy.unused` when no code reads it. The rule also covers `export declare namespace` in a `.ts` file, nested namespaces (the member name is a dotted path such as `Outer.Inner.x`), and a namespace that merges with a class, a function or an enum. A member counts as used when code reads it as `N.a` (as a value or a type), destructures it, aliases it with `import x = N.a`, or reads it inside the namespace body. When the namespace object leaves its chain (an argument, an alias, a spread or `Object.keys(N)`), every member counts as used. Fallow does not check declaration files, `declare global`, module augmentations, local namespaces, or a namespace that an entry point exports. The findings appear in JSON (`unused_namespace_members`), SARIF, CodeClimate, compact, markdown and human output, in the LSP, the MCP server, the VS Code extension, the GitHub Action and the GitLab template. A finding on a run with an incomplete import graph carries `reachability_caveats[]`. Ten arrays carry it: `unused_namespace_members[]` joins the nine arrays that carried it before. Suppress a finding with `// fallow-ignore-next-line unused-namespace-member`. The rule defaults to `warn`, so the CLI exit code does not change. The dead-code count gate of the GitHub Action counts `warn` findings unless `fail-on-issues` is `false`. To turn the rule off for generated files, set `"unused-namespace-members": "off"` in `overrides`. `fallow migrate` maps the `namespaceMembers` issue type of a migrated config to this rule. (Closes [#4209](https://github.com/fallow-rs/fallow/issues/4209))
- The parse cache version changes because the cache now stores the namespace member reads of each file. The first run after the upgrade parses every file again.

### Fixed

- **A declaration merge is no longer a duplicate export.** A module that exports a class, a function or an enum and a namespace of the same name (`export class C {}` and `export namespace C {}`) gave a false `duplicate-exports` finding. Fallow now counts one module once per export name.
