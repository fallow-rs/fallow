### Fixed

- **The Git hooks and the agent gate now run the project-local fallow first.** The pre-commit hook of `fallow init --hooks`, the Lefthook job and the gate of `fallow agent install` now try `./node_modules/.bin/fallow` before a `fallow` on `PATH`. The project pins its fallow version, and a global install can have another version or no type-aware companion. The order is now the same as the order of the plugin gate. `fallow agent status` reports `gate-path-version` only when the project has no `node_modules/.bin/fallow`, because only then does the gate run the `fallow` on `PATH`. A project that pins an old fallow now runs that version in its hooks. The Git hook needs fallow 3.43.0 or later for `audit --staged`, and it names the runner and the fix when the version is older. The agent gate names the devDependency or the install on `PATH`, whichever it ran. Installed hooks keep the old order until you refresh them: run `fallow hooks install --target git --force` for the Git hook, copy the job that `fallow hooks install --target git` prints into `lefthook.yml` for a Lefthook job, and run `fallow agent install` for the agent gate (`fallow agent status` reports an old gate script as `stale` with the `gate-script-refresh` action). (Closes [#4628](https://github.com/fallow-rs/fallow/issues/4628))
