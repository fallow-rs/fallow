### Added

- **`constant-parameter` reads type evidence in type-aware mode.** With `--type-aware` (or `typeAware.enabled`) and the rule on, the rule reports two more kinds of finding. The new reason `unused-default` reports a parameter with a default where each call passes a value whose type excludes `undefined`, so the default never applies. The rule also reads the methods of exported classes, with the reasons `never-passed` and `unused-default`; the finding names the method as `Class.method`. These findings carry `evidence: "type-aware"`, the human and CI output add `(type evidence)`, and SARIF puts `evidence` in the result properties. A type does not prove a run-time value, so the explanation says that an `any` value, a cast, or data from outside the program can break the claim. The TypeScript companion checks only the candidates that the closed-world gate selects. It gives no evidence without `strictNullChecks`, for an index read or a call result without `noUncheckedIndexedAccess`, for a binding that code writes after its declaration, for a class field that can stay unset, for a narrowing by a type guard, or when an assertion, an `any` value or a `@ts-*` comment is on the path to the argument. A method gets no finding when a decorator, an overload, a member of a dependency type, a name that the platform calls, a reference that is not a call, an unresolved, computed or reflective member access, a file outside the program of the class, or a structurally compatible type can hide a call. `_meta.type_aware.call_evidence` counts the candidates, the findings and each abstention reason. Without type-aware mode, the output of the rule does not change. The editor session reports only the findings that the call facts prove.
  (Closes [#4516](https://github.com/fallow-rs/fallow/issues/4516))
