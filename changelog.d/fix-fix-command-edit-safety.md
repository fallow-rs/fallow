### Fixed

- **`fallow fix` skips a file with a bare CR line ending.** The fixers split lines on LF, but the parser also ends a line at a bare CR. An edit in such a file used offsets from the wrong line. The file is now skipped with `skip_reason: "mixed_line_endings"`, as a file with mixed CRLF and LF line endings is, and the run exits with code 2.
- **`fallow fix --type-aware` removes more unused class methods.** A class field with no `;`, such as `value = 1`, ends at a line break only when the next member cannot continue it. When the next kept member starts with `[` or `*`, the fixer refused the removal of the method between them, because the result did not parse. The fixer now writes a `;` in front of that kept member (`;[key]() {}`), so the removal applies and the class still parses.
- **`fallow fix` applies the scope flags.** `--workspace`, `--changed-workspaces`, `--changed-since`, the package baselines and a diff from `--diff-file`, `--diff-stdin` or `FALLOW_DIFF_FILE` narrowed the `dead-code` report but not the fixes, so a scoped `fix` run edited the whole project. `fix` now plans only the findings that `dead-code` reports with the same flags. An unknown workspace exits with code 2. This also applies to the `workspace` parameter of the MCP `fix_preview` and `fix_apply` tools and to the GitHub Action with `command: fix`.
