### Fixed

- **Text output keeps each project string on its line.** A file path, an import specifier, an export name, a package name or a config value can hold a line break or another control character. The human, compact and Markdown formats, the `Gates:` note, `fallow list`, the warnings on stderr and the `message` of each `workspace_diagnostics[]` entry now print such a character as a visible escape, for example `\n` or `\u{001B}`. Before, a line break in a name started a new output line, and a CI runner could read that line as a workflow command. A terminal sequence in a name, for example one that hides all later text, is escaped too, with colors on and off. JSON output keeps the raw path and name fields.
- **`next_steps[].command` stays one shell command.** The `trace-unused-export`, `trace-deprecated-export` and `scope-workspaces` steps now put a value with a space or a shell character in single quotes, for example `fallow dead-code --trace 'src/(auth)/lib.ts:helper'`. Before, such a value broke the command or added a second one. A plain path and name stay unquoted. A trace step skips an export whose path or name has a line break.
