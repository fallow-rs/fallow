### Fixed

- **Text output keeps each project string on its line.** A file path, an import specifier, an export name, a package name or a config value can hold a line break or another control character. The human, compact and Markdown formats, the `Gates:` note, `fallow list`, the baseline notes and the warnings on stderr, and the `message` of each `workspace_diagnostics[]` entry now print such a character as a visible escape, for example `\n` or `\u{001B}`. Before, a line break in a name started a new output line, and a CI runner could read that line as a workflow command. A terminal sequence in a name, for example one that hides all later text, is escaped too, with colors on and off. JSON output keeps the raw path and name fields.
- **`next_steps[].command` stays one shell command.** The `trace-unused-export`, `trace-deprecated-export`, `scope-workspaces` and `recheck-baseline` steps now put a value with a space or a shell character in single quotes. The trace steps write the target as `--trace=<target>`, for example `fallow dead-code --trace='src/(auth)/lib.ts:helper'`, so a target that starts with `-` stays the flag value. Before, such a value broke the command or added a second one. A plain path and name stay unquoted. A step skips a value with a line break. The inspect command in the mutation section of a pull request comment uses the same quoting rule for `--root`.
