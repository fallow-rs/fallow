### Fixed

- **`fallow audit` no longer reports a complexity finding as introduced when a refactor moves the function to another file.** Under `--gate new-only`, a complexity finding matches its base finding by file path and function name. A refactor that splits one file into several files gave each moved function a new path, so the audit reported the function as `introduced` and the gate failed for code that the change did not write. A finding without a base finding now takes the base finding of the same function name from another changed or deleted file. A moved function with equal values is `inherited`. A moved function that grew is `worsened`. When two or more functions of one name moved and their values changed, the name does not identify them, and they stay `introduced`. A whole-file rename already kept its findings inherited.
