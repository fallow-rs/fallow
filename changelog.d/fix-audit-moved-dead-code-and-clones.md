### Fixed

- **`fallow audit` no longer reports unused code and clone groups as introduced when a refactor moves the code to another file.** Under `--gate new-only`, each attribution key holds the file path, and git reports a rename only for a whole file. A refactor that splits a file gave the moved code a new path, so the audit reported a moved unused export, a moved unused class member or a moved clone group as `introduced`. A finding of an unused symbol (an export, a type, a class or enum member, a component prop and the like) now takes the base finding with the same rule and the same symbol in another changed or deleted file, when no head finding holds that base finding and the change wrote a line with the symbol in the new file. An export that the change made unused without a new line stays `introduced`. Findings that name no symbol of a file, such as dependency and suppression findings, do not match. A clone group takes the base group with the same token count, line count and text, when each file of that base group is a changed or deleted file. Each base finding covers one head finding, so a copy of moved code stays `introduced`. A finding in a file that the change did not touch never matches. A clone group whose text changed in the move, for example after a formatter rewrap, stays `introduced`. (Closes [#4670](https://github.com/fallow-rs/fallow/issues/4670))
