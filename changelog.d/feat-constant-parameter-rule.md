### Added

- **New opt-in rule `constant-parameter` reports a parameter that each call passes in one way.** It reports a parameter of a module-scope function when each visible call passes the same value (`identical-argument`), or when no call passes an optional parameter (`never-passed`). The same value is the same literal, or the same `const` with a literal initializer or the same enum member, also through imports and re-exports. For a destructured options parameter such as `{ retries = 3, signal }`, the rule reports each key that no call sets, or that each call sets to the same value, with the field `option_key`. The finding lists the value, the call count, up to 20 calls, and the count of conditions that test the parameter. Turn it on with `fallow dead-code --constant-parameters` or `rules.constant-parameters`; the default is `off`, and the rule has no automatic fix. The rule reports only when it sees each caller: it skips public API and entry-point exports, dynamic imports, CommonJS, a function used as a value, template files, `eval`, framework auto-imports, functions that a test file declares, and functions with fewer than 2 calls (`MIN_CALL_SITES` is 2; it has no config key). A recursive call that passes a parameter or an option key on unchanged does not count as a call for it. A file with a parse error, or an HTML page with an inline script, blocks only the functions that its import specifiers can reach. JSON, SARIF, CodeClimate, markdown, compact, human output, baselines, LSP, MCP, the Node bindings and the VS Code extension carry the finding. A test file is a caller unless `--production` is set. When the rule is on, the dead-code count gate of the GitHub Action counts its findings unless `fail-on-issues` is `false`. The first run after the upgrade parses each file again, because the cache format changed.
  (Closes [#4491](https://github.com/fallow-rs/fallow/issues/4491))
