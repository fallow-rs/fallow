### Fixed

- **A React Native platform file that imports from its base file no longer reports a re-export self-loop.** In a React Native or Expo project, `Button.ios.tsx` often contains `export type { ButtonProps } from "./Button"`. Fallow resolved `./Button` with the Metro platform extensions, so the specifier pointed back to `Button.ios.tsx`. Fallow then logged a `Re-export self-loop detected` warning, reported a `self-loop` finding in `re_export_cycles`, and could report the re-exported type as unused. Now, when a platform extension makes a specifier resolve to the importing file, fallow resolves the specifier again without the platform extensions, the same as TypeScript. The specifier then resolves to `Button.tsx`. When no base file exists, the resolution does not change. A specifier that names the platform, such as `./Button.ios`, keeps its target. The graph cache version changes, so the first run after the upgrade rebuilds the graph cache.
