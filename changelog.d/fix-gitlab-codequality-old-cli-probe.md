### Fixed

- **The GitLab CI template no longer fails the job when the installed fallow has no `fallow report`.** When `FALLOW_VERSION` is empty, the template installs the fallow version that `package.json` pins. Before, a pin older than 3.4.2, for example `2.91.0`, stopped the Code Quality step with `unrecognized subcommand 'report'` and exit code `2`. Now the template runs the analysis again with `--format codeclimate`, which these versions support. This second run has the same scope as the first run, but it does not save a baseline or a snapshot again. The job log names the installed version, where the version came from, and the minimum version 3.4.2. When the older fallow cannot make the report in that way either, for example with `--report-path-prefix` in `FALLOW_ARGS`, the template writes an empty Code Quality report, shows a warning that tells you to update the fallow dependency or set `FALLOW_VERSION`, and continues the job. Mutation entries need a current fallow and are not in the report from the older path.
  (Closes [#4481](https://github.com/fallow-rs/fallow/issues/4481))
