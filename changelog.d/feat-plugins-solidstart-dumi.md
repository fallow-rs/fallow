### Added

- **Built-in SolidStart plugin.** The `solid-start` plugin activates from the `@solidjs/start` dependency. It makes `<appRoot>/app.{tsx,jsx}`, `<appRoot>/entry-client.{tsx,jsx}`, `<appRoot>/entry-server.{tsx,jsx}` and each module under `<appRoot>/<routeDir>` entry points. Before, fallow reported these files and all the modules that they import as unused files. Route files get the `default`, `route` and HTTP method exports. The plugin reads `appRoot`, `routeDir`, `extensions` and `middleware` from the `solidStart()` call in `vite.config.*` and from `defineConfig()` in the version 1 `app.config.*`. The defaults are `src` and `routes`.
- **Built-in dumi plugin.** The `dumi` plugin activates from the `dumi` dependency. It makes each demo file that a `<code src="...">` tag of a Markdown file names an entry point, and credits its `default` export. Before, fallow reported these demo files as unused files. A relative `src` is read from the directory of the Markdown file, and a `src` that starts with `/` from the package root. Fallow now also analyzes the hidden `.dumi` directory: the theme `builtins`, `slots`, layouts and `plugin`, the `pages` routes and the `global`, `app` and `loading` files are entry points. The plugin reads `.dumirc.ts` and `.dumirc.js`: it credits the imported packages and the `plugins` and `presets` packages, and it reads `alias` as path aliases.
