### Added

- **`workspaces.settings` sets `ignoreDependencies` and `includeEntryExports` for each workspace.** A key is a workspace root as `fallow list --workspaces` prints it, or a glob such as `packages/*`. A workspace gets the global `ignoreDependencies` plus the list of each key that selects it. An unused dependency uses the workspace of its `package.json`, and an unlisted dependency uses the workspace of the importing file. For `includeEntryExports`, an exact root wins over a glob, and a longer glob wins over a shorter glob. The `--include-entry-exports` flag still turns the check on everywhere. A key that selects no workspace gives a warning, and an unknown key under `workspaces` gives a warning too. The global keys do not change.
- **`supportEntry` declares entry points that do not run in production.** In a normal run, a `supportEntry` file keeps its imports reachable, the same as `entry`. In production mode (`--production` or `production: { deadCode: true }`), fallow leaves a file that only `supportEntry` matches out of the analysis. Its imports then credit no export, file or dependency. A file that `entry`, a plugin or a `package.json` field also declares stays an entry point.
- **`fallow migrate` keeps per-workspace settings and production entry markers.** Workspace `ignoreDependencies` and `includeEntryExports` become `workspaces.settings` keys, and the migration no longer merges them into the global list or drops them. When a config marks at least one entry with a trailing `!`, the marked patterns become `entry` and the unmarked patterns become `supportEntry`. A config without a marker keeps every pattern in `entry`.
