### Fixed

- **The editor `fallow.production` setting gives the rules of production mode.** The language server set production mode after config resolution, so it still reported unused dev dependencies and unused optional dependencies that `fallow dead-code --production` does not report. The feature-flags API had the same order. Both now pass the setting to the config loader before resolution.
- **MCP tools read `FALLOW_PRODUCTION*` on both routes.** The CLI route of an MCP tool honored `FALLOW_PRODUCTION`, `FALLOW_PRODUCTION_DEAD_CODE`, `FALLOW_PRODUCTION_HEALTH` and `FALLOW_PRODUCTION_DUPES` from the server environment, and the in-process route did not. So one tool gave other findings for the same project when an unrelated parameter selected the other route. The in-process route now reads them with the precedence of the CLI: the tool parameter, then the variable of the analysis, then `FALLOW_PRODUCTION`, then the config. The programmatic API and the Node bindings still take explicit options only.
- **The Code Mode `combined` tool reports config-enabled coverage gaps.** With the `coverage-gaps` rule on in the config, bare `fallow` reports coverage gaps, and the in-process `combined` route did not. `fallow_api::run_combined` now reports them too.
- **More commands honor `--config` and `--allow-remote-extends`.** `fallow report --from` refused a remote `extends` entry also with `--allow-remote-extends`. `fallow audit` compared a change of the `--config` file against a discovered config of the base, so it did not report the code that the change made unused. `fallow audit --staged`, `fallow plugin-check` and the `fallow coverage upload-*` commands ignored one or both flags. Each of these commands now reads the `--config` file with the trust policy of `--allow-remote-extends`.
